# Hospital Management System

Django-based Hospital Management System covering the full patient
lifecycle plus a wide set of premium extras - multi-branch support,
ambulance tracking, vaccination records, insurance claims, QR/barcode
check-in, a doctor calendar, global search, multi-language UI, a theme
customizer, automatic backups, and more.

## Installation

**Prerequisites:** Python 3.10+ and pip.

```bash
# 1. Extract the project and open a terminal in the hospital/ folder

# 2. Create and activate a virtual environment
python -m venv venv

# Windows:
venv\Scripts\activate
# Mac/Linux:
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Apply database migrations (creates tables, default roles, etc.)
python manage.py migrate

# 5. Run the development server
python manage.py runserver
```

Now open http://127.0.0.1:8000/login/ in your browser.

**Existing login:** username `Jay`, password `Hospital@123`
(this is the account that was already in the database - please log in
and change this password immediately from Profile -> Change Password).

**To create your own admin account instead:**
```bash
python manage.py createsuperuser
```

**If something looks wrong after install:** run `python manage.py check`
first - it will point out any configuration issue before you dig further.

## What's new in this round

- **Real-time-ish in-app notifications** - a bell icon in the navbar polls
  every 20 seconds for unread alerts (low stock, expiring medicine, stale
  pending lab tests, upcoming vaccination doses). Click "Mark all read" to
  clear them. Alerts are generated by `Hospital/alerts.py`, triggered
  opportunistically on dashboard load (throttled to once per 5 minutes)
  and also runnable directly via `python manage.py generate_alerts` - the
  latter is what you'd schedule via cron for alerts to appear even when
  nobody has the dashboard open (see `DEPLOYMENT.md`).
- **Medicine expiry alerts** - medicines expose `is_expiring_soon` (within
  30 days) and `is_expired`, shown as badges on the medicine list and
  included in the automatic alert notifications above.
- **Hospital Analytics page** (`/analytics/`, Admin only) - patient gender
  split, doctors by department, a 12-month admissions trend, top 5
  diseases treated, average bill amount, and appointment completion rate.
  All real data, separate from the main dashboard's charts.
- **Rule-based department suggestion** - while adding a patient, typing a
  disease/symptom shows a hint like "Suggested department: Cardiology".
  **This is plain keyword matching, not AI/ML** - it's intentionally
  simple so the project has zero external AI dependencies or API keys.
  See the `DEPARTMENT_KEYWORDS` dict and `suggest_department()` in
  `Hospital/views.py` if you want to swap it for a real LLM call later
  (the endpoint's JSON response shape is designed to stay the same either
  way, so the frontend wouldn't need to change).
- Re-verified every previously-built "optional" feature still works:
  multi-branch, multi-language, automatic backup, insurance claims, QR
  check-in, barcode printing, and email notifications were all re-tested
  end-to-end in this round.

## Performance, validation & security hardening

- **Query optimization:** patient/doctor list, search, and dashboard views
  now use `select_related()` for their foreign keys (doctor, branch,
  patient), eliminating N+1 query patterns that were firing one extra
  query per row.
- **Caching:** the dashboard's auto-refresh endpoint (`/dashboard/stats.json`)
  caches its aggregate counts for 10 seconds via Django's cache framework,
  and is invalidated immediately whenever a relevant record changes - so
  frequent polling doesn't repeatedly hit the database for the same
  numbers, without ever showing stale data for more than a few seconds.
- **Pagination:** all list views (patients, doctors, bills, medicines,
  appointments, lab tests, insurance claims, audit log) are paginated.
- **Form validation added:**
  - Duplicate-patient detection (same name + phone warns instead of
    silently creating a second record)
  - Age bounds on patients/doctors, phone number format checks
  - Non-negative price/quantity/charges, expiry dates can't be in the past
  - **Appointment double-booking prevention** (same doctor, same date and
    time is rejected with a clear message)
  - Ambulance vehicle numbers are already unique at the database level;
    Django's ModelForm validation catches a duplicate and shows a friendly
    error instead of crashing.
- **Security:**
  - Every view that reads or writes data requires login (audited all view
    functions to confirm - only the login/register pages are public, as
    they should be).
  - File uploads (patient/doctor photos, lab/medical report attachments)
    are now capped at 5MB and, for report attachments, restricted to
    pdf/jpg/jpeg/png/doc/docx extensions - a basic guard against abuse or
    disguised file uploads.
  - CSRF protection is Django's default and applies to every form in the
    app (`CsrfViewMiddleware` is enabled).

## UI/CSS polish

While going through the codebase for this round, two real inconsistencies
turned up and were fixed rather than just adding new CSS:

1. The Theme Customizer (added in an earlier round) was overriding the
   site's existing gradient buttons with a flat `!important` color,
   visibly *downgrading* the premium look whenever an accent color was
   picked. Fixed so switching accent colors re-tints the same gradient
   style instead of flattening it.
2. Dark mode had no styling for several newer Bootstrap components used
   throughout the app - modals (webcam capture), offcanvas panels (theme
   customizer), dropdown menus (language switcher), and form
   inputs/selects. These would have rendered as bright white panels
   against the dark background. Extended `.dark-mode` rules to cover all
   of them consistently.

## Honest notes on scope (things that look "real" but are demoed/simplified)

- **Ambulance tracking** is not connected to real GPS hardware - the map
  (Leaflet.js) reads whatever coordinates are stored on the Ambulance
  record and polls every 5 seconds; there's a manual "Update Location"
  form to simulate movement.
- **Online payment** marks a bill Paid for demo purposes only - no money
  moves. See `DEPLOYMENT.md` section 8 for wiring up a real gateway.
- **SMS notifications** log the message rather than sending a real SMS -
  see `notify_sms()` in `Hospital/views.py` for plugging in Twilio.
- **"Real-time" dashboard** uses polling, not WebSockets (which would need
  Django Channels + Redis - heavier than this project needs).
- **Multi-language support** wires up the full i18n framework and
  translates the main navigation as a working proof-of-concept; extending
  it to every string is a matter of running `makemessages`, translating,
  then `compilemessages` again.
- **Automatic backup** is a real command - actually running it on a
  schedule needs cron/Task Scheduler, since Django has no built-in
  scheduler (steps in `DEPLOYMENT.md`).

## Bugs fixed along the way

- `update_patient.html` was a bare, unstyled HTML form with a **plain
  text input for the doctor field** instead of a dropdown - since
  `doctor` is a foreign key, submitting free text failed form validation
  silently, and the form had no `enctype`, so photo uploads never worked
  either. Editing a patient was effectively broken. Rewritten to match
  "Add Patient" - verified working end to end.
- **Export Patients to Excel** crashed (wrote a Doctor object into a
  cell) - fixed to write the doctor's name.
- **Database Backup** crashed (a view function named `settings` shadowed
  Django's settings import) - fixed with an import alias.
- Removed duplicate URL registrations and a duplicate class definition.
- The dashboard's chart used hardcoded fake numbers - replaced with real
  revenue and appointment data.
- The existing `Jay` account had no usable password - set as above.
- No `requirements.txt` existed, and the bundled `my_env` virtualenv only
  had Django installed - removed it, added a proper `requirements.txt`.

## REST API

Full CRUD under `/api/` for patients, doctors, bills, medicines,
appointments, medical records, lab tests, wards, and beds, plus read-only
audit logs - all with token authentication:

- `POST /api/auth-token/` with `username`/`password` -> returns a token
- `GET/POST /api/patients/`, `/api/doctors/`, `/api/bills/`,
  `/api/medicines/`, `/api/appointments/`, `/api/medical-records/`,
  `/api/lab-tests/`, `/api/wards/`, `/api/beds/`, `/api/audit-logs/`
- Supports filtering (`?status=Admitted`) and search (`?search=jay`)
- Use header `Authorization: Token <token>` on requests.
